# Rosewood V6.22 Change Map

## Scope

V6.22 separates conservatively identified test applications from ordinary family
records in authenticated Enrolment planning and adds application-created-date sorting.
It does not delete, migrate or modify an application and does not change any family
question, answer, requirement, validation, upload, signature or submission workflow.

## Record Type

The authorised dashboard adds a response-only `recordCategory`:

- `test` when an explicit stored test marker exists, a student or parent/guardian name
  begins with Synthetic or Test, the email uses the reserved `example.test` domain, or
  its local part contains a separated synthetic, canary or test marker
- `family` otherwise

Enrolment planning defaults to **Family applications**. Staff can select **Test
applications** or **All records**, and test rows carry a visible **Test record** label.
This category is not stored in DynamoDB, written to Google Sheets, included in an
application answer or used as an admissions status.

## Application Date

The planning toolbar offers newest and oldest application-date sorting, plus the
existing entry-year/level ordering. The date is the authoritative application
`createdAt` value and is displayed on each planning row. Last activity remains based on
`updatedAt` and is not reinterpreted.

## Compatibility

EOI `rosewood-eoi-2026.21` and Application `rosewood-application-2026.22` preserve the
V6.21 family contracts. Editable drafts upgrade through the existing conditional
definition path without answer transformation. Submitted applications and signature
evidence remain pinned to their original definitions.

## Verification

Verification covers response-only classification, test-email aliases, no stored
mutation, default family filtering, test/all filters, newest/oldest/cohort sorting,
missing dates, desktop/mobile layout, accessibility, immutable hashes and the complete
backend regression suite.
