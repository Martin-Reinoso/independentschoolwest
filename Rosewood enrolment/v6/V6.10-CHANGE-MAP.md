# V6.10 EOI Address Assistance Change Map

## Scope

V6.10 extends the existing optional Google Places address helper to the Expression of
Interest primary-contact address. It does not add, remove, rename or reinterpret an EOI
or Application answer key.

The helper fills only these existing EOI controls:

- `eoi_address`
- `eoi_suburb`
- `eoi_state`
- `eoi_postcode`
- `eoi_country`

The family must review and may edit every populated value. Manual entry remains fully
available when Google, billing, quota, JavaScript or the runtime configuration is
unavailable. Doctor/practice address remains manual.

## Runtime And Privacy Boundary

The public EOI loads browser configuration from `GET /v6/eoi/config`. The response is
restricted by the service origin allowlist and has `Cache-Control: no-store`. The API
key is never committed to HTML or JavaScript. A website browser key is necessarily
visible to a browser and is not treated as a server credential; Google Cloud website
and API restrictions are the security boundary.

Google receives only text entered in its separate suggestion control. Rosewood requests
address components for a selected result and does not request or store a Place ID,
coordinates, search history, formatted-address payload or device geolocation. The EOI
itself remains one-page and is not autosaved; only the reviewed structured values are
submitted to Rosewood.

## Compatibility

- Current EOI contract: `rosewood-eoi-2026.10`
- Current Application contract: `rosewood-application-2026.10`
- Storage schema: unchanged from V6.9
- EOI and Application contracts: byte-for-byte equivalent data contracts to V6.9
- Google Sheet and Drive projections: unchanged

Application advances because it shares the newly pinned family JavaScript. Editable
older applications upgrade through the existing conditional version mechanism with all
answers and revisions preserved. Submitted applications never upgrade.

## Verification Gate

1. The public EOI config endpoint returns the configured provider only for an allowed
   origin and does not cache the response.
2. The key is absent from all static repository assets.
3. An Australian suggestion fills address, suburb, long-form EOI state, postcode and
   country.
4. Manual entry remains usable when the endpoint or Google is unavailable.
5. The EOI can be completed on desktop and mobile without horizontal scrolling.
6. No EOI is submitted during synthetic UI verification.
