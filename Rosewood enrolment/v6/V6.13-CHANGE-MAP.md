# V6.13 Document Upload Recovery Change Map

## Scope

V6.13 is an immutable presentation and interaction release. It preserves the V6.12 EOI
and Application data contracts, answer keys, backend validation and storage behavior.

```text
EOI:         rosewood-eoi-2026.13
Application: rosewood-application-2026.13
```

V6.12 and every earlier definition remain addressable. Submitted records, saved draft
answers and successfully uploaded documents are not rewritten or deleted.

## Corrected Failure

Previously, an invalid file created a failed entry in the browser upload map. Selecting
a different valid file created another entry but left the failed entry behind. The card
warning, sticky Upload failed state and Next-page guard therefore remained active even
after the valid replacement uploaded.

V6.13 reconciles a non-empty replacement selection before starting it:

- completed failed entries in the same document category are removed;
- the category is rendered immediately so its stale inline warning disappears;
- a global `DOCUMENT_UPLOAD_FAILED` summary is cleared;
- the replacement starts through the existing encrypted staging and Drive flow;
- uploaded files, active transfers and failures in other categories remain intact; and
- cancelling the file picker does not clear a retryable failure.

## Deliberate Non-Changes

- Accepted types remain PDF, PNG and JPEG, from 1 byte through 10 MB per file.
- Retry continues to use the selected file already held in the current browser session.
- No uploaded document, DynamoDB record, Drive file or staged S3 object is deleted by
  browser reconciliation.
- No question, required answer, schema, Sheet projection, signature or email changes.
- EOI advances only because the family HTML and JavaScript are shared and repinned.
