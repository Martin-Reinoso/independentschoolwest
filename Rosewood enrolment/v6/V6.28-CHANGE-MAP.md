# V6.28 Reviewed Family Communications Change Map

Date: 3 September 2026

## Outcome

Admissions staff can prepare one reviewed application-update email for selected child
applications in the same family, see the exact copy each recipient will receive and
send separate private messages. The communication appears in the history of every
selected child application without merging or editing those applications.

## Staff Workflow

1. Open **Family communications** and choose an application.
2. Select the submitted children to include from the same invitation.
3. Select recipients available across every selected application.
4. Prepare the exact backend-rendered preview.
5. Open every recipient tab and check desktop/mobile HTML plus plain text.
6. Explicitly mark the exact content reviewed.
7. Explicitly send the reviewed family email.

The prepared template chooses one of three variants:

- `entry_2027`: all selected children seek 2027 entry;
- `later_entry`: all selected children seek entry after 2027;
- `mixed_entry`: the selection contains both 2027 and later entry years.

## Safety Boundary

- All selected applications must share one invitation and be `submitted` or
  `staff_review_required`.
- A recipient must be explicitly contact-permitted on every selected application.
- Each recipient receives a separate email; no recipient list is exposed through To or
  Cc.
- The subject contains no child name.
- The reviewed content hash binds template revision, family invitation, child set,
  entry details and exact recipient copies.
- Send rerenders and rechecks current data. A changed permission or context blocks the
  old reviewed copy.
- The send transaction is version-conditional and idempotent by operation ID.
- Submitted answers, documents, signatures, application IDs and revisions are never
  changed.

## Storage

One `FAMILY_COMM` master owns immutable recipient copies. An invitation index supports
family history, and each selected `APP` has a link to the same master. Review writes the
complete graph and audits atomically. Send conditionally updates that graph and creates
one durable outbox event per recipient in a second atomic transaction. SES feedback is
recorded per recipient copy. Google Sheets are not part of this workflow.

## Compatibility

EOI `rosewood-eoi-2026.27` and Application
`rosewood-application-2026.28` preserve the V6.27 family question and validation
contract. The family browser allowlist includes V6.26, V6.27 and V6.28 so active and
historical records remain readable after release.
