# Rosewood V6.20 Change Map

## Scope

Phase 1 adds a read-only **Admissions overview** as the default authenticated staff
workspace. It applies selected operational ideas from the EnquiryTracker reference
without copying its product, styling or broader CRM scope.

This release does not add an offer, acceptance, decline, event, appointment, class
group, bulk-message or enrolment-decision workflow. It does not change a family-facing
question, required answer, upload, signature, invitation or submission rule.

## Canonical Application Stages

The backend calculates one stage for every child application:

| Stage | Authoritative application state |
| --- | --- |
| Not started | `invited` |
| In progress | `in_progress` |
| Awaiting signatures | `pending_signatures` |
| Staff review | `staff_review_required` |
| Application complete | `submitted` |

**Application complete** means every required Application for Enrolment signature has
been recorded. It does not mean the child is enrolled, accepted or offered a place.
Counts use child applications rather than families because one invitation can hold
multiple children.

## Overview And Filters

The portal displays:

- five stage cards
- a stage distribution
- entry-year and entry-level mix
- search by student or application reference
- entry year, entry level and application-stage filters
- a responsive staff-attention queue

The same active filters apply to all overview elements. Missing entry answers are
labelled, not inferred. Existing **Enrolment planning**, **Applications**, link-request,
EOI and email-operation workspaces remain available and unchanged.

## Staff-Attention Rules

The queue is calculated at dashboard-request time and currently flags:

- failed or delayed current invitation/signature email delivery
- expired, inactive or missing application access for an editable application
- an in-progress application with no saved activity for at least seven days
- a submitted-for-signature application outstanding for at least three days
- an application explicitly requiring staff review
- missing entry year or entry level after the application has started

These flags are prompts only. Rendering or filtering the queue performs no write,
message delivery, token renewal, status change or admissions decision. **Review** uses
the existing authorised, audited application-detail operation.

## Privacy And Data Boundary

DynamoDB remains authoritative. The summary correlates application, invitation and
encrypted SES-feedback records. Google Sheets remain replaceable projections.

The aggregate `planningSummary` and its attention items omit recipient email, date of
birth, health answers, documents, raw SES message/event identifiers, signature images,
invitation tokens and network metadata. Historical records and saved family answers
are not migrated or rewritten.

## Compatibility

EOI `rosewood-eoi-2026.19` and Application
`rosewood-application-2026.20` preserve the V6.19 question, answer, validation,
projection, submission and signature-evidence contracts. They repin the updated staff
assets and the browser supported-version list. Editable older drafts upgrade through
the existing conditional definition transaction without answer transformation.
Submitted records and signature evidence remain pinned to their original definitions.
