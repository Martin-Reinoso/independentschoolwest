# V6.11 Production Hardening Change Map

## Scope

V6.11 is an immutable EOI and Application release. It preserves the V6.10 data
contracts and stored answer keys while correcting active interface catalogues and
strengthening delivery, recovery and repository controls.

Current contracts:

```text
EOI:         rosewood-eoi-2026.11
Application: rosewood-application-2026.11
```

V6.10 and every earlier definition remain addressable. Submitted records never
upgrade. When an editable older draft is upgraded through the existing conditional
workflow, all answers and immutable revisions are preserved.

## Family Interface

- The active V11 occupation list removes the accidental `Germany` entry, sorts the
  catalogue and corrects outdated or misspelled labels including `Phamacist`,
  `Postman`, `Salesman`, `Storeman`, `Hair Dresser`, `Hostess` and truncated
  `Panel Shop Prop`.
- Applications pinned to V10 or earlier continue to render their original occupation
  values so a saved legacy answer is never hidden or silently reinterpreted.
- The V11 Parent / Carer commitments no longer include fee payment, photography/social
  media permission or a Grade 12 withdrawal-notice clause. Those matters are outside
  the Application for Enrolment boundary. V10 and earlier continue to render their
  pinned wording.
- EOI submission uses a stable browser idempotency key for safe retries.

## Backend Resilience

- EOI creation stores its idempotency record atomically with the EOI, audit and outbox
  work. Legacy clients receive a bounded payload/day/network deduplication boundary.
- Network and email-based EOI hourly/daily throttles run before creating a Drive
  snapshot.
- If a transaction fails after an external Drive or signature artifact is created,
  the service attempts compensating deletion and logs only bounded operational data.
- Outbox delivery is capped at eight attempts. Exhausted events move to a retained
  failure record and emit a CloudWatch metric/alarm instead of retrying forever.
- Every outbox email stores the SES message ID with non-sensitive tags and optional
  signer-task correlation for 90 days.

## SES Delivery Feedback

The production stack owns a named SES configuration set, encrypted SNS event topic,
Lambda subscription and a dedicated retained KMS key. SES `send`, `delivery`,
`deliveryDelay`, `bounce`, `complaint`, `reject` and `renderingFailure` events are:

1. normalised without recipient addresses;
2. deduplicated by message ID, event type and provider timestamp;
3. recorded in restricted audit and Operations `Email Events` projections;
4. correlated to a pending guardian request when applicable; and
5. ranked so a late lower-value event cannot overwrite a final delivery/failure state.

If SES reports a signature email before its outbox correlation transaction completes,
the Lambda fails that SNS invocation transiently so SNS retries after the index exists.
A successful SES API call remains `accepted_by_ses`; it is not displayed as delivered
until SES reports delivery.

## Repository And Release Gates

- GitHub Actions runs the locked Node 22 backend tests and deployment build.
- A static-site check verifies tracked local HTML/CSS references.
- A public-data check rejects attendee/booking export filenames, personal tabular
  exports and high-confidence AWS key, private-key, Slack webhook and GitHub-token
  patterns.
- Two archived Rosewood one-pagers now resolve the correct root logo path.
- The deployment build pins all V11 family/policy assets by SHA-256.

## Deliberate Non-Changes

- DynamoDB remains authoritative; Google Sheets remain replaceable projections.
- Google Drive remains the approved submitted-document store.
- Acceptance, Decline and the Enrolment Agreement remain separate non-writing
  previews.
- GuardDuty and cross-region replication remain outside the approved scope.
- Legal retention/deletion, named staff identities, collection/consent approval and
  upload-malware-scanning policy remain governance decisions and are not invented by
  this release.
